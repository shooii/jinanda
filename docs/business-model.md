## 二、价格

美元基准价，本地化统一走 `payments.priceFor()`（汇率 × 购买力 × 当地取整习惯）。

| 档位 | 月付 | 年付 | 年付折合 | 省 |
| --- | --- | --- | --- | --- |
| Plus | $7.99 | $59.99 | $5.00 / 月 | 37% |
| Pro | $14.99 | $119.99 | $10.00 / 月 | 33% |

> 相比原先的 $5.99 / $45.99：北美偏低，欧洲含税后毛利被 VAT 吃穿。新价在德国（VAT 19%）、法国（20%）下扣税扣分成后仍留有正毛利。

## 三、试用

| 项 | 规则 |
| --- | --- |
| 时长 | **7 天** |
| 档位 | **Pro**（给最高档，让用户完整感知价值，而不是给要卖的那档） |
| 次数 | 同一账号**仅一次**（`trialUsed` 锁） |
| 提醒 | 剩余 **3 天**时提醒一次；试用开始即明示结束日期 |
| 期间计费 | 不扣款 |

7 天而不是 14 天：北美/欧洲的订阅转化在 7 天附近最陡，14 天会显著拉高「试用完就走」的比例，也更容易撞上 Visa / Mastercard 的试用转付费提醒要求。

## 四、试用结束后怎么收费

分两条路径，付费墙与会员页都如实写明：

**A. 绑卡试用（默认）**
试用结束当天，按用户选定的档位与周期自动扣款，状态变为 `active`。

**B. 不绑卡试用**
到期直接降级到 Free，**不产生任何费用**，状态变为 `expired`。

## 五、降级后保留什么

这是本模型最重要的一条：**到期不锁设备**。翻译耳机断供等于设备变砖，会直接换来 1 星与退款。

**保留**
- 每日 20 次即时翻译与 10 分钟同传
- 已下载的 1 个离线语言包继续可用
- 历史记录、词汇、会议纪要全部保留，不删除
- 已单独买断的离线包永久有效

**失去**
- 超出 1 个的离线包被锁定（续费即恢复，**不重新下载**）
- 会议只转写不生成纪要与待办
- 通话同传与观影同传暂停
- 跨设备同步暂停，本地数据仍在

## 七、状态机

`resolveEntitlement()` 的判定顺序：

```
试用未到期        → trialing   (tier = pro)
订阅有效 + 自动续费 → active
订阅有效 + 已取消   → canceled  (仍 paid，到期末才降)
订阅已过期        → expired   (tier = free)
从未开通          → none
```

`past_due` / `grace` / `paused` / `revoked` 已在类型里预留，等服务端 webhook 接入后启用（见 `docs/global-payments-design.md` 第六、七节）。

## 八、代码里怎么用

```ts
const { entitlement, tier, quotas, quotaOf, gate, consume } = useUsage()

// 动作发生的那一刻判门禁，不要进页面就拦
const result = gate("dialogue")
if (!result.allowed) {
  setPaywall(true)   // result.reason: feature_locked | quota_exceeded
  return
}

// 成功之后记一笔
consume("dialogue", 1)
```

`Usage` 台账存在 `localStorage` 的 `lingo.usage`，跨日清日额度、跨月清月额度均在读取时惰性滚动，用户隔天打开不会先看到昨天的余量。

正式环境应改为服务端计量（`docs/api-contract.md` 的 `/v1/usage`），本地只做乐观展示与离线兜底。

## 九、待定项

这些数字我按北美/欧洲的通行区间给了初值，但需要真实数据校准：

1. Free 的每日 20 次 / 10 分钟是否足够「让人上瘾但不满足」
2. Plus 会议 300 分钟是否偏高（对个人用户可能过剩，对企业用户不够）
3. 试用给 Pro 而不是 Plus——转化率更高还是更低的真实差异
4. $249 Lifetime 会不会侵蚀订阅收入
5. 离线包 10 个对 Plus 是否太多（可能该压到 5 个，把差额留给买断）
